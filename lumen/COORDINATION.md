Chaque agent travaille dans la **même copie** du dépôt (`/home/claude/prismarcade`, branche `lumen-v05`), sur des fichiers **qu'il possède**. Ne pas modifier un fichier d'un autre agent : écrire une demande dans la section « Demandes » ci-dessous (et lire régulièrement ce fichier).

## Règles
1. Ne pas lancer `git commit`, `git push`, `git checkout`, `git stash` : le chef de projet (Claude principal) commit et publie.
2. Serveur de test : chacun utilise **son propre port** (GAMEPLAY 8771, GRAPHISME 8772, SON 8773, QA 8774) et ne tue que son propre serveur.
3. Les fichiers des autres peuvent être en cours de modification : un échec ponctuel venant d'un fichier qui n'est pas le tien → attends 1 minute et relance avant de conclure.
4. Contrats partagés (ne pas casser) : `window.__lumen` (API de test), les ids de thème (`THEMES`/`AMB`), les noms d'événements `G.emit`, le format des données `js/data/*`.
5. Pas de régression : l'Aube (Acte I) et la Forêt doivent rester jouables ; `node tools/verify.mjs`, `node --check` sur chaque fichier modifié, et les tests Playwright (`tests/`, `/home/claude/tests/*.py`) doivent passer.
6. Le **SON** expose une API simple que le GAMEPLAY et le GRAPHISME peuvent appeler : `audio.sfx(nom)` / `audio.music(thème)` (voir Demandes pour les noms de sons).
7. Le **GRAPHISME** expose des fonctions de modèles/animations dans `world/` ; si GAMEPLAY a besoin d'un nouvel accessoire visuel (balise de verre, grappin, pylône…), il le demande ici.
8. Ne jamais publier les règles Firestore.

### [SON] API audio (publiée — tout est optionnel, un nom inconnu ne lève jamais d'exception, jouer avant le 1er geste utilisateur est ignoré sans erreur)
Import : `import { audio, music } from './engine/audio.js'` (inchangé ; `G.audio` = `audio`). Compatible avec les appels existants (`audio.sfx(nom)`, `audio.chime`, `audio.chord`, `audio.tone`, `audio.noise`, `audio.set/get`, `audio.unlock`, `music(thème, niveau)`).
- `audio.sfx(nom, opts?)` — `opts` : `{ x, z }` (position monde → pan/distance si `audio.listener` est appelé), `pan` (-1..1), `vol` (0..1), `pitch` (multiplicateur), `color` ('r','g','b','y','m','c','w'), `weapon` ('lame'|'lourde'|'distance'|'magie'), `ground` ('herbe'|'pierre'|'bois'|'eau'|'verre'|'terre'), `voice` (id/nom PNJ → timbre du « blip » de dialogue), `hard` (atterrissage).
- `audio.music(thème, intensité 0..1)` — thèmes : `title, village` (Havre-Aube), `puzzle` (salles d'énigmes), `lande, sanctuaire, foret` (Forêt de Verre), `vitrebourg, lisiere, temple, interieur` (auberge/maisons), `combat, boss, boss2` (boss phase 2), `canopee`, `phare`, `victoire`, `null` (fondu au silence). Fondu enchaîné automatique (~2,5 s). Peut être rappelé chaque seconde (idempotent). L'ambiance (vent, oiseaux…) suit le thème toute seule.
- **Adaptatif sans rien brancher** : les sfx de combat (`hit`, `hurt`, `kill`, `swing*`…) montent la « tension » de la musique courante (percussions, basses), qui redescend après ~8 s.
- `audio.ambience(préset|{couche:niveau}|null)` — presets = noms de thèmes ; couches : `wind, birds, insects, water, mist, hum (résonance temple), fire, glassrain, distant`. Un objet fusionne avec le préset courant (ex. `audio.ambience({ fire: 0.8 })` près d'un feu ; `{ fire: 0 }` pour l'enlever).
- `audio.listener(x, z, yaw)` — position/orientation de l'écoute (à appeler chaque frame, bon marché) pour la spatialisation des sfx avec `{x,z}`.
- `audio.step(ground, opts?)` = `sfx('step_'+ground)` ; `audio.note(color, opts?)` = `sfx('note_'+color)`.
- `audio.bossPhase(n)` : n=1 → `boss`, n=2 → `boss2`.
- Volumes : `audio.set({ master, music, sfx, ambience, voice, muted })` (0..1), `audio.get()`. Persistés aussi par le son lui-même (`localStorage lumen.audio`).
